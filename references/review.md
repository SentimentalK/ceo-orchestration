# Review

验收 Worker 交付时使用本文件。

## 规则

1. Worker 的报告不是证据。证据只有 Diff、你运行的命令输出和 CI 结果。
2. 先选风险最高的交付项检查，例如核心逻辑、公开接口、数据迁移和安全边界。
3. 被检查的项都通过时，其余项正常 Review，不逐行细查。
4. 任一项失败时，Worker 的报告不再可信。逐项检查它的全部交付。
5. 高风险改动可以再派一个 FRONTIER 模型做只读 Review。它给出的结论只作参考，验收由你决定。

## 检查项

任一项失败，都不能验收。

1. **范围**：`git diff` 只涉及白名单内的文件。没有密钥，没有未授权的依赖。
2. **正确性**：行为符合 Spec，不只是让测试通过。没有硬编码的预期答案。
3. **测试**：既有测试仍然通过。核心逻辑的缺陷有回归测试，旧代码在该测试上会失败。实验脚本靠验收命令的输出验收。新增的测试必须能失败：断言源码里有某字符串、函数存在、文件非空之类的测试算缺陷。
4. **证据**：SHA、测试结果和 CI 结果都来自实际运行的命令。

## 裁决

| 裁决 | 条件 | 动作 |
| --- | --- | --- |
| 通过 | 四项检查都有证据 | 集成，并按 AGENT.md R7 写回 |
| 返工 | 缺陷能在 Spec 范围内修复 | 写 Bounded Repair Spec，交给原 Worker session |
| 结束 | 需要改变 Ticket，或返工达到上限 | 按 AGENT.md R8 结束 |
