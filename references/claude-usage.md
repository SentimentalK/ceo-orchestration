# Claude 订阅的额度

起付费批次或长跑前、给长跑脚本定速度时、向用户报额度时使用本文件。本文件只适用于 Claude 订阅。其他订阅按 `models.json` 里该 plan 的 `quota` 说明处理；没有读数办法的，额度问题请用户看。

## 读数

1. `tools/claude_usage.py` 输出一行：5 小时窗口的用量和重置时刻、周窗口的用量和重置时刻、周池里各模型子上限的用量。`--json` 输出原始返回；`--log <文件>` 同时追加一行，用于校准。
2. 它只读 Claude Code 保存的 token。不打印、不写进日志、Spec 或票，不自己刷新。返回 401 时等 Claude Code 下次运行后再读。
3. 接口没有公开文档。读不到时请用户看 `/usage`，并在汇报里说明。
4. 读的时机：起付费批次或长跑之前；每个批次结束；每次调速之前；早上续跑之后；waiter 超时检查点。最短间隔 10 分钟。

## 窗口

1. 两个窗口都在 `resets_at` 整体清零，不是滚动窗口。控速看 `resets_at`，不自己数。
2. 所有 Claude 用量共用这两个窗口：Conductor、Master、Worker、脚本里的 `claude -p`、用户自己的使用。

## 线

1. 5 小时窗口：到重置时用量不超过 85 %。
2. 周窗口：给用户留至少 20 %。用户另给停线时按用户的。
3. 超线：5 小时超了，降速或睡到重置；周超了，写可恢复的 STOP 并报用户。不换模型绕过。

## 控速

1. 校准：相邻两次读数的百分点差，除以同期完成的工作单元数，得到每单元占两个窗口各多少。
2. 允许速率 =（线 − 当前用量）÷ 每单元占比 ÷ 距重置的可跑小时数。两个窗口各算一次，取小的。
3. 长跑脚本自己读数控速，每 10 到 15 分钟读一次，不用固定的每小时上限。读失败时退回保守的固定上限并记一行日志。
4. 正在跑的脚本不为换控速方式中途重启，等批次边界。
5. 向用户报额度时写来源和读数时刻。
