# 实验、训练、数据类工作

票涉及实验、训练、数据采集，或要向用户报指标时使用本文件。

## 开工前（Conductor）

1. 开票或批准设计检查点前，先写"预判"块：预计产出（数量、费用、时间）；结果能证明什么、不能证明什么；好结果与坏结果各长什么样，各把下一步引向哪里。对设计至少做一轮 self-challenge，存活的质疑写进票。预判先入记忆仓库，汇报时对照。
2. 预计可用量不到训练集 5 % 的来源不单独撑一条消融臂。
3. 验收场景不得用来调参。涉及门限、阈值的波次，Spec 明写"在独立集上标定，不在验收场景上调"。
4. 预算写具体数字：API 折算花费上限、计算小时上限、样本先小量后放量的阶梯。
5. Spec 的环境说明加写：计算资源当前是否空闲、环境路径、git 外数据（语料、权重、输出目录）的绝对路径。

## 执行（Master）

1. 长任务用 nohup 后台跑并落日志。
2. 写入共享数据目录的任务串行跑在主工作区。
3. 调研选型时写清每个候选的成本与准确率。

## 汇报（Conductor）

1. 每个成功率旁边写明是哪个模型、有哪些工具，不只写 profile 名。
2. 报关键指标（F1、成功率等）时用白话交代五件事：正确答案的来源（人标、系统自动标还是模型标）；测试集怎么切，模型是否见过；怎样算"对上"；TP / FP / FN 的实际个数；这个分不衡量什么。
3. 用户问现状时，带上计算资源在不在用。
